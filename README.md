# Replication Package: Coding Alone
Anonymised replication package (double-anonymous review).

## Contents
- `notebooks/` : the full executable pipeline (Google Colab), in order:
  00_setup · 01_sampling_frame · 02_population_events ·
  03_metrics_population · 04_deep_fetch (language enrichment) ·
  05_mentorship_mdi (newcomer/NRR) · 07_ai_era_analysis (ITS/DiD) ·
  08_within_repo_and_figures · 09_robustness (permutation inference,
  break dates, washout, programming-language-universe DiD + validity
  checks) · 10_swr_validation (live GitHub API audit).
  There is no notebook 06; numbering is contiguous otherwise.
- `data/` : derived, de-identified tables (monthly ecosystem series,
  language-month panel, within-repo estimates, ITS/DiD outputs,
  robustness grids, SWR audit records). Without BigQuery access these
  suffice to verify every number in the paper, to re-fit the
  interrupted time series from the ecosystem series, and to re-run the
  full difference-in-differences, permutation inference, and validity
  checks from `language_month_panel.csv`. Re-estimating the
  repository-level fixed-effects models requires re-extracting the
  repository-month panel via notebooks 01-03.
- `figures/` : the paper's Figure 1 as generated by the pipeline.

## Requirements
- Google Colab (free tier suffices for analysis notebooks).
- To re-run extraction from scratch (notebooks 01–05): a Google Cloud
  project with BigQuery access to the public `githubarchive` dataset.
  Set PROJECT_ID in each notebook's first cell. Extraction scans
  several TB; the free sandbox covers analysis but full re-extraction
  may require billed capacity. All queries are cost-guarded (dry-run
  caps) and fully resumable (job-id reattach + Drive checkpoints).
- Notebook 10 needs a GitHub token (Colab secret `GITHUB_TOKEN`),
  ~1,800 REST calls, well under the hourly limit.

## Reproducing the paper's results from derived data only
Open notebooks 07–10 and run the analysis cells against `data/`
(paths are set in each notebook's config cell). Tables I–III and all
robustness numbers in the paper derive from these files.

## Data ethics and de-identification
All data originate from public GitHub events (GH Archive). Derived
tables contain no actor logins; repositories appear only via numeric
IDs in audit records, as required for resolvability checks. No
attempt should be made to re-identify individuals.

## Provenance notes
- Analysis window 2018-01 .. 2025-06 (collection to 2026-06; final 12
